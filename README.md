# CobbleSynergy — CobbleLeague 타입 시너지 애드온

CobbleLeague 0.7.1을 **수정하지 않고** 옆에 같이 설치하는 애드온입니다.
던전(랜덤 선택 모드)에서 영입한 임시 파티의 타입 구성을 세어 TFT 특성처럼 시너지를 켭니다.

- **서버와 모든 클라이언트에 설치해야 합니다.** 서버는 효과를 적용하고, 클라이언트는 HUD를 그립니다. 싱글플레이는 jar 하나로 됩니다.
- 필요 모드: Cobblemon 1.7.3, CobbleLeague 0.7.1, Fabric API, Fabric Language Kotlin (COBBLEVERSE 1.7.42에 포함)
- 던전 밖의 일반 전투, 대여전·덱 지정전에는 적용되지 않습니다. 관장전은 플레이어 쪽에만 적용됩니다.

## 규칙

- 복합 타입은 두 타입 모두에 1마리씩 셉니다. (예: 리자몽 = 불꽃 +1, 비행 +1)
- 단계는 **누적되지 않고**, 조건을 만족하는 가장 높은 단계 하나만 적용됩니다. 그래서 높은 단계에는 아래 단계 효과가 함께 들어 있습니다.
- `=1` 단계는 그 타입이 **정확히 1마리일 때만** 켜집니다.
- 효과는 모두 **Showdown에 원래 있는 전투 기믹**(벽, 순풍, 장판, 트릭룸, 필드, 날씨, 도발, 씨뿌리기, 아쿠아링, 버티기, 원념, 랭크업)을 그대로 씁니다. 기술 피해를 직접 늘리거나 줄이는 효과는 노말·강철에만 있습니다.
- **약점과 면역은 바꾸지 않습니다.** 씨뿌리기는 풀에게, 화상은 불꽃에게 통하지 않는 것처럼 원래 상성 판정을 따릅니다.
- 무적 방지 상한: 받는 피해 감소 최대 20%, 턴당 회복 최대 12.5%.

## 시너지 표 (기본값)

## 발동 순서와 충돌 규칙

전투 시작 직후(첫 턴 행동 선택 전) 아래 순서로 적용됩니다.

1. **진영 효과**: 우리 진영(벽·순풍·신비의부적·흰안개·오로라베일), 상대 진영 장판(스텔스록·압정·독압정·끈적네트)
2. **상대 선두 상태**: 도발, 씨뿌리기
3. **날씨·필드·트릭룸**: 아래 충돌 규칙에 따라 적용
4. **처음 나올 때 효과**: 랭크업, 아쿠아링 (교체해 처음 나오는 포켓몬도 그때 적용)

양쪽 진영의 처리 순서는 전투마다 무작위입니다. 진영 효과나 상대 상태는 서로 겹치지 않아서 순서에 따른 차이가 없습니다.

**날씨·필드가 겹칠 때**
- **특성·기술이 먼저**: 가뭄·잔비·일렉트릭메이커 같은 특성으로 이미 날씨나 필드가 깔려 있으면 그쪽이 우선이고, 시너지는 대기열에 들어갑니다.
- **마릿수가 많은 쪽 먼저**: 양쪽 시너지가 서로 다른 날씨(또는 필드)를 원하면, 그 시너지 타입의 마릿수가 많은 쪽이 먼저 깝니다. 같으면 무작위입니다.
- **대기열**: 밀린 쪽은 대기하다가 앞의 날씨·필드가 끝나는 턴에 이어서 발동합니다. 6턴 안에 자리가 나지 않으면 취소됩니다.
- **같은 효과는 합침**: 양쪽이 같은 날씨를 원하면 한 번만 발동하고, 더 긴 턴 수를 씁니다.
- 한 팀 안에서 불꽃(쾌청)과 물(비)처럼 충돌하는 경우도 같은 규칙(마릿수 우선, 나머지는 대기)을 따릅니다.
- 전투 중에 플레이어가 쓰는 날씨·필드 기술은 원래 게임 규칙대로 덮어씁니다.

## UI (TFT 스타일)

- **사이드 HUD**: 오른쪽 가운데에 Cobblemon 타입 아이콘과 마릿수, `2 › 4 › 6` 형태의 단계 진행을 표시합니다. 테두리 색: 동 = 첫 단계, 은 = 중간, 금 = 최고, 보라 = 단독(=1), 회색 = 비활성.
  - 아무 화면(전투, F4, C, 채팅)이 열려 있거나 F1을 누르면 숨겨져서 기존 UI를 가리지 않습니다.
- **상세 화면 (기본 키 U)** — Y 는 Tom's Storage 가 사용: 18개 시너지 전체, 단계별 효과, 다음 단계까지 남은 마릿수를 보여 주고, HUD 표시 방식과 위치도 바꿀 수 있습니다.
- 전투가 시작되면 그 전투의 시너지가 채팅에 표시됩니다. `/synergy`로도 확인할 수 있습니다.

## 테스트 빌드 (`cobblesynergy-0.1.0-test.jar`)

`gradle.properties`의 `test_build=true`일 때 만들어집니다. 배포용은 `false`로 바꿔 빌드하세요.

- **로그 파일**: `<게임 폴더>/logs/cobblesynergy-test.log`에 시너지 계산, 전투 주입 내용, 검증 PASS/FAIL, 전투 종료 요약이 쌓입니다.
- **서버(월드) 시작 시 자가 점검**: CobbleLeague 연동 지점, 설정, 시너지 설명을 점검합니다. 전투를 자동으로 시작하지는 않습니다.
- **게임 내 자동 테스트**: 월드를 열고 10초 뒤 타입 × 단계마다 AI 트레이너끼리 전투를 돌려(플레이어 불필요) Cobblemon 실제 데이터로 시작 효과·지속 턴을 검사합니다.
- **테스트 전투 버튼**: U 화면 아래쪽에서 타입과 마릿수를 고르고 **테스트 전투 시작**을 누릅니다.
  - 그 타입으로 만든 **임시 파티의 복사본**과, Cobblemon NPC AI를 쓰는 **가짜 트레이너**가 싸웁니다. 내 파티와 던전은 건드리지 않습니다.
  - 시작 2초 뒤 Showdown이 실제로 보낸 전투 메시지(벽 설치, 날씨 시작 등)를 확인해 PASS/FAIL을 기록합니다.
- 실제 던전 전투와 페어리 확률 강화도 테스트 빌드에서는 같은 로그에 기록됩니다.

## 개발자용 테스트

```
gradle build                 # 컴파일 + 설계 검사 6개, build/synergy-sides.json 내보내기
node test/sim/synergy-sim.js "<프로필>/showdown" build build/sim-result.log
```

시뮬레이션은 Cobblemon에 들어 있는 Showdown으로 실제 전투를 돌립니다. 모든 타입 × 마릿수의 효과와 지속 턴, 버티기 1회, 원념, 날씨 충돌 규칙을 검사합니다. 현재 결과는 **312 PASS / 0 FAIL**입니다.

## 동작 방식 (개발 메모)

- 파티 읽기는 CobbleLeague의 공개 API(`LeagueMod.service.draftParty`, `isDraftPokemon`)를 씁니다. 페어리 확률 강화만 리플렉션(`LeagueService.runs`, `DrawOddsBoosts.odds/usedRound`)을 쓰고, 실패하면 그 기능만 꺼집니다.
- 전투 효과는 `BATTLE_STARTED_POST` 5틱 뒤 Showdown에 `>eval`로 이벤트 핸들러를 등록하는 방식입니다(`src/main/resources/cobblesynergy/battle.js`). 이 파일은 한 줄로 합쳐 보내므로 `//` 주석을 쓰면 안 됩니다.
